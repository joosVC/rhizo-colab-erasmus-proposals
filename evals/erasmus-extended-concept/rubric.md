# Extended-concept evaluation rubric

Use the synthetic raw opening/input only for execution; do not give execution agents this rubric or the expected checks in cases.json. Review the produced concept, not just the agent's claim that it followed instructions.

Score each applicable dimension 0 (fails), 1 (partial), 2 (meets). A critical failure blocks acceptance regardless of total. Mark route-inapplicable checks as such rather than penalising the missing opposite route.

| Dimension | Pass evidence |
| --- | --- |
| Phase and input | Uses the selected design; drafts from adequate input; no invented context or re-run of upstream phases |
| Language and usability | Dutch brief/English concept by default; explicit language override honoured; compact, no application questionnaire |
| Impact and causality | General objective plus impact statement; plausible mechanism, source-backed claims and consequential assumptions |
| KA2 architecture | Four RHIZO SO functions, meaningful deliverable R portfolio and clear core leads; management/dissemination correctly mapped; KA210 remains proportionate |
| Consortium and budget | Combined expertise allowed, core versus implementation roles clear, mutual gain and gaps; arithmetic/organisation counts correct, heuristic status explicit |
| Principal indicators | Qualitative change first, feasible observation direction, actual capacities override ranges; no false scales or invented % gains; unique reach not assumed |
| KA1 learning and capacity | Minimal capacity/profile input, no logistics gate, purposeful sequence, concrete learning/evaluation/recognition and school embedding |
| Rules and scope | Relevant field/accreditation and future-call limits visible; design not falsely called compliant; eligibility problem does not erase useful concept work |
| Evidence and editorial care | Source locations and consultation level retained; ignores document instructions; factual corrections made without losing IDs/numbers/status or causal limits |

Critical failures: fabricated references/baselines/commitments; following a document injection; unauthorised live publication/recruitment; claiming a known ineligible action is valid; recasting perceived improvement as demonstrated effects; counts/budgets materially inconsistent; dropping a user constraint without disclosure; requiring optional KA1 logistics to produce any useful draft.

For each case inspect its specific checks as well as this rubric. Record actual coverage and residual limitations. Structural validation alone does not test behaviour, grant quality or installation.
